# 小学数学 · 竖式闯关

给小学生练计算用的互动网页：**一年级到六年级一条线闯关**，每一题都用竖式呈现，可以用拨轮转或键盘打两种方式答题，答错能看**边动边念**的逐步讲解（动画演示 + 中文朗读）。

**线上地址：<https://sx2.9i9i.cn>**（打开是首页：计算闯关 / 知识点讲解 / 学习统计 三个入口，iPad 上直接玩）

## 页面清单

| 文件 | 内容 |

| `vertical.html` | **竖式闯关**。33 个关卡、拨轮输入、动画 + 语音讲解；带 `?review=N` 时进入第 N 阶错题练习 |

| `learn/lesson.html` | 一节讲解课：动画舞台 + 字幕 + 语音 + 10 道练习（`?id=g4bu3` 这样指定单元） |

页面互相链接，纯静态、无外部依赖，双击就能在浏览器打开。

## 学习统计与错题本（`stats.html`）

三处练习（竖式闯关、知识点讲解、纲要页）都写到同一个 `localStorage`（`ms_stats_v2`），统计口径：

- 竖式：**整道题全对**才算一次答对（数字和进位都对）
- 选择题：一次选择算一次
- 错题练习本身也计入题量和正确率
- 数据只在本机，换浏览器或清缓存会丢；页面底部可导出 JSON

### 错题六阶

| 阶 | 含义 |
|---|---|
| 一阶 | 刚做错的题，默认都在这儿 |
| 二阶 | 一阶练对过一遍，隔一次再验证 |
| 三~六阶 | 继续答对就往上走，每阶题目更少、更“顽固” |
| 已掌握 | 六阶都答对，出本；以后又做错会自动回到一阶 |

答错一律退回一阶。这样「练到六阶」的都是真正记住的题，而不是碰巧答对。

两种练习入口按题型分：计算题跳回 `vertical.html?review=N` 复用整套竖式交互，选择题在统计页内做（选项每次打乱）。

## 闯关规则

- 一关 = 一个年级里的一个具体内容，**连对 10 题**自动通过并进入下一关
- 答错即中断连对，从头累计
- 进度存在浏览器 `localStorage`（key `pm_path_v2`），关掉再打开会接着上次的关卡
- 家长想直接跳到某个年级：展开顶部面板 → 「解锁全部关卡」

## 两种答题方式

顶部面板里可切换：

| 方案 | 说明 |
|---|---|
| **A 拨轮转动** | 每位是一个数字轮，手指按住上下拖动，数字实时跟手、松手吸附；上下各露出半格相邻数字，像调密码锁。**iPad 上最好用** |
| **B 键盘输入** | 在竖式格子里直接打字，自动跳下一格 |

**进位 / 退位**是独立的操作，两种方式都能用：标记就在竖式正上方那一行，点一下就循环 `+1 → +2 → +3 → 空`（减法为 `−1 → −2 → −3 → 空`）。乘法里需要更大的进位时，循环上限会按正确答案自动放宽（例如进 8 就能点到 +8）。没标或标错，检查时那一位会亮红圈。

## 讲解

点底部的「讲解」，竖式会**一边动画演示一边用中文念出来**，动画和语音同一步走：

- 正在算的那一列整体亮起并轻微放大
- 竖式下方浮出这一位的算式（如 `5 + 9 = 14`、`百分位 0 + 7 = 7`、`21 × 2 = 42`），气泡的小箭头指着那一列
- 同一句话从喇叭里念一遍："个位：5 加 9 等于 14。满十，写 4，向十位进 1。"
- 进位标记同时"弹"到上方对应位置，结果数字逐位落下（拨轮会自动滚到正确的数）
- 右侧步骤列表同步高亮当前行

节奏是**念完一句才走下一步**：数字 0.43s 后就落下，语音多长就等多久，不会出现"动画跑完了话还没说完"。

### 语音从哪来

讲解的声音**不是系统发音**，是服务器合成的成品音频：

| 顺序 | 引擎 | 音色 |
|---|---|---|
| 1 | 火山引擎豆包语音 2.0（声音复刻） | 昕哥原声 `S_bjuVnqqj2`，`speech_rate=5` |
| 2 | 微软 Edge 在线语音 | 云希 `zh-CN-YunxiNeural`（火山不可用时自动切） |
| 3 | 浏览器 `speechSynthesis` | 系统中文音色（前两条都拿不到才用） |

流程：题目一出现，页面就在后台把这道题的 4–5 句并行合成好（`GET /sx2-tts?t=...`），孩子审题那几秒足够；点「讲解」时直接播 `blob:` 音频，通常感觉不到等待。同一句只合成一次，缓存在服务器 `/opt/sx2-math/tts-cache/`。

**音频是「首次合成 + 落盘缓存」**，不是提前录好的文件：竖式的讲解句带随机数字（「个位：8 加 3 等于 11」），每道题都不一样，没法预录；所以第一次请求时合成并写成 mp3，之后就是纯静态文件（命中 13ms）。知识点讲解的文案是固定的，那部分会整批预生成成静态 mp3，不走实时合成。

### 后期处理（裁首尾 + 停顿清零 + 降噪）

火山返回 **48k PCM**，云希回 **mp3**（先解码成 PCM），再走同一条链：

```
裁首尾 → 停顿清零 → 边缘淡化 → anlmdn×2 + afftdn → highpass=80,lowpass=11000
```

- 前三步在 Node 里按 PCM 样本直接做（`server/sx2-tts.js`），滤镜交给 ffmpeg（`/opt/sweettalk-wework/bin/ffmpeg`，静态 7.0.2）
- **只吃 48k 输入**（所以不能再用 24k 直出，那会先损失高频）
- 输出 48k / 96kbps mp3
- 知识点讲解的静态音频用同一套参数（`tools/postproc.py`），改一处记得改另一处
- ffmpeg 缺失或超时 12s 时自动回退到 24k mp3 直出，不会哑

- 语音内容就是右侧步骤的原话，念之前把 `÷ × + − =` 换成「除以 / 乘 / 加 / 减 / 等于」，避免读出符号怪音
- 开关在顶部折叠面板的「讲解方式」里（`localStorage: pm_voice_v1`），关掉后只播动画、按固定节奏走
- 网关代码在 `server/sx2-tts.js`，Key 只存服务器 `/opt/sweettalk-wework/.sx2-tts.key`，**页面上没有任何密钥**

### 并发上限（重要）

火山账号的并发达到了 10，但同一个 Key 还有别的服务在用，所以本服务**只占用 5 个名额**，绝不越界：

| 项 | 值 | 环境变量 |
|---|---|---|
| 火山并发 | 5 | `SX2_VOLC_CONCURRENCY` |
| 云希并发 | 4（独立池，不吃火山名额） | `SX2_YUNXI_CONCURRENCY` |
| 队列上限 | 40 条，超出直接回 503 让前端回落 | `SX2_TTS_MAX_QUEUE` |
| 排队超时 | 12s，超时视为「忙」并换另一个引擎 | `SX2_TTS_QUEUE_TIMEOUT` |

几个细节：

- 名额只算**真正打到上游**的请求，缓存命中不占名额，所以「我们来看这道题」这种高频句几乎不消耗并发
- 名额在**响应流真正结束后**才释放（而不是收到最后一帧就放），否则本地已放行、上游还算在跑，实测会冲到 6
- 排队超时/队列满不算火山故障，不触发 90s 冷却，也不会把用户请求打成 503——先试另一个引擎，都忙才由前端回落到系统 TTS

本机可查实时状态（公网 403）：`curl --resolve sx2.9i9i.cn:443:127.0.0.1 "https://sx2.9i9i.cn/sx2-tts?stats=1"`

> iPad 的规矩：页面必须被手指点过一次才允许出声。所以页面在任何一次 `pointerdown` 时先用一个 60ms 静音把复用的 `<audio>` 元素解锁，之后换 `src` 播句子都不会被拦。

长除法这类很高的竖式，气泡会跑到屏幕外，此时页面会自动小幅滚动把它带回来。

右侧「讲解步骤」默认是空的（只留一句提示），点了「检查」或「讲解」才把每一步列出来，免得孩子先抄答案。

底部四个按钮：**检查 / 讲解 / 再做一次 / 换一题**。做错了点「再做一次」就把作答清空、步骤收回，同一道题从头再做一遍（题号和算式都不变）；答对后 2 秒会自动换题，这期间点「再做一次」也能拦住。

### 内容怎么维护

内容按**单元片段**存放，改哪个单元只动那一个文件：

```
learn/data/lessons/src/g4bu3.js     ← 源文件（手写/生成，一个单元一个）
learn/data/lessons/g4b.js           ← 构建产物（整册，页面按册懒加载）
learn/data/lessons/ids.js           ← 已上线单元清单（构建时自动生成）
```

```bash
node tools/build_book.js            # src/ → 按册产物 + ids.js
node tools/check_lessons.js         # 结构 / 场景白名单 / 语音可读性 / 题目校验
node tools/fix_quiz_dist.js         # 打散正确答案位置（A/B/C 各约三分之一）
```

`check_lessons.js` 会拦住三类常见问题：语音里出现 `+ − × ÷ = < >` 这类会被念错的符号、场景类型拼错、答案全挤在 B。

### 讲解音频是预生成的静态文件

知识点文案固定，所以**整批预生成**，页面直接 `<audio src="audio/g4bu3-2.mp3">`，不再实时合成：

- 文件：`learn/audio/<单元id>-<第几步>.mp3`，48kHz 单声道 96kbps
- 合成：`node tools/dump_say.js g4b > jobs.json` → `python3 tools/gen_audio_book.py jobs.json learn/audio --workers 4 --force`
- 并发 4（火山账号 10 个名额里有 5 个归本服务，留出余量）
- 页面加载时只取当前单元的十几句；拿不到静态文件才回落到 `/sx2-tts` 实时合成，再不行才用系统 TTS

#### 后期链（`tools/postproc.py`）

比竖式那套多三步，原因是「啵」声：

| 步骤 | 做什么 | 为什么 |
|---|---|---|
| 裁首尾 | 切掉首尾低于 −28 dBFS 的段，前留 120ms、后留 180ms | 火山每句首尾各带约 0.3s 底噪 |
| **停顿清零** | 句号级停顿（≥300ms、电平低于语音 12dB）整段填真静音，两端 30ms 淡出/淡入 | **降噪后残留的吹气声会变成「啵」** |
| 边缘淡化 | 首尾各 8ms 淡入淡出 | 防硬切出「嗒」 |
| 降噪 | `anlmdn ×2 + afftdn(nr=8,nf=-35) + highpass=80 + lowpass=11000` | 两级 anlmdn 压嘶声，`afftdn` 收底噪 |

「啵」的成因值得记一笔：火山在句号停顿处会带一小段吹气/唇齿杂音（约 −41 dB）。原声里噪声底也是 −43 dB，混在一起听不出来；一旦降到 −60 dB 以下，它就变成孤零零的一团，听感就是「啵」。**它是真实声源，降噪压不掉**，只能把整段停顿替换成静音。

试听样本留在仓库 `voice-samples/probe/`（同一句三种处理：原声 / 只裁首尾+降噪 / 完整链）。临时对照页 `/voice-test/` 已下线。

## 技术要点

- 单文件 HTML + 原生 JS，无框架、无构建步骤
- 竖式用 CSS Grid 渲染，列宽由 JS 按位数生成（小数点列 24px，其他 58px；移动端 20/50px），每个 cell 显式指定 `grid-row` 避免回流错位
- 题目由构造器生成：`buildAddSub`、`buildMul`、`buildMulN`（多位数乘法，两行部分积都是待填）、`buildDiv`（长除法，先贪心取够比除数大的前缀再起商）
- 每个构造器返回 `{expr, cols, rows, inputs, carries, steps, answer}`，渲染、判题、讲解都基于这份结构
- 每一步还带一个 `ex` 字段（这一位的简明算式），讲解气泡直接用它，不必再解析文字说明
